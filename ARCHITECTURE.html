PDF Voice AI - Arquitectura del Sistema

Sistema de IA agnóstico (Gemini / DeepSeek / GLM) para chat de voz sobre documentos, organizado como Proyectos (Racks) → Cuadernos → Archivos.

4. Diagrama de Flujo: Chat con RAG



1. Usuario escribe pregunta (o habla por voz)
        │
        ▼
2. POST /api/chat  {query, rack_id, provider, api_key, …}
        │
        ▼
3. RackManager.get_async(rack_id)  → validación de proyecto
        │
        ▼
4. DocumentManager.get_context_string_async(query, rack_id, notebook_ids)
        │
        ├─► query_async() → embedding de la pregunta (sentence-transformers)
        │         │
        │         ├─ Neon:  SELECT … WHERE project_id = rack_id ORDER BY embedding <=> :embedding
        │         │           LIMIT :limit
        │         │
        │         └─ Chroma: collection.query(query_embeddings=…, n_results=k, where=…)
        │
        ▼
5. Contexto recuperado (fragmentos etiquetados por cuaderno y archivo)
        │
        ▼
6. AIProviderFactory.create(provider) → proveedor concreto
        │
        ▼
7. provider.build_rag_prompt(context, query, system_instruction, operating_instruction, notebook_catalog)
        │
        ▼
8. provider.generate(system_prompt, user_prompt) → (answer, tokens)
        │
        ▼
9. ChatResponse { answer, provider, model, sources, notebooks_used, tokens_used }
        │
        ▼
10. Frontend muestra respuesta + fuentes + reproduce voz (SpeechSynthesis)

8. Providers de IA - Factory Pattern



AIProviderFactory.create(provider, api_key, model, **kwargs)
        │
        ├─ AIProvider.GEMINI   → GeminiProvider       (google-generativeai SDK)
        ├─ AIProvider.DEEPSEEK → DeepSeekProvider     (OpenAI-compatible, api.deepseek.com)
        └─ AIProvider.GLM      → GLMProvider          (OpenAI-compatible, open.bigmodel.cn)

BaseAIProvider (ABC)
  - __init__(api_key, model, temperature, max_tokens)
  - abstract: provider_name, default_model, generate(system, user) → (text, tokens)
  - build_rag_prompt(context, query, language, system_instruction, operating_instruction, notebook_catalog)


9. Flujo de Ingesta de Documentos



Archivo subido (PDF / txt / md / csv / json / log)  ≤ 50 MB
        │
        ▼
1. Validación: extensión permitida + tamaño
        │
        ▼
2. Extracción de texto
   - PDF: pypdf.PdfReader → texto por página, máximo 500 páginas
   - Texto: lectura directa
        │
        ▼
3. Chunking (_chunk_text)
   - Límite: CHUNK_SIZE = 1000 chars, solapamiento CHUNK_OVERLAP = 200
   - División en párrafos (\n\n) o frases (. )
        │
        ▼
4. Embeddings: sentence-transformers (all-MiniLM-L6-v2) → 384 dimensiones
        │
        ▼
5. Persistencia:
   - Neon: INSERT INTO document_chunks (…, embedding vector(384), …)
             ON CONFLICT (project_id, notebook_id, filename, doc_hash, chunk_index) DO UPDATE
   - Chroma: collection.upsert(ids, embeddings, documents, metadatas)
        │
        ▼
6. doc_hash = sha256(texto)[:16] → deduplicación automática
